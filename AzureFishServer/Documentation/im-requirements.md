# IM 需求与接口实施范围

> 2026-09-27：按本次确认的“私聊＋群聊＋消息同步；媒体单独规划”实施。服务端提供本机虚构账号的文本 IM，客户端聊天仍是本地模拟。本文的“已实现”不代表生产可用或 App 已接入。

## 需求分解与取舍

| 领域 | 必须满足的行为 | 本轮交付 |
| --- | --- | --- |
| 身份与用户发现 | 身份来自 Bearer，设备匹配会话；查找不泄露凭据 | 复用账号服务；精确账号查询最小公开资料 |
| 私聊 | A→B 与 B→A 同一会话；离线前先取得权威 ID | 唯一用户对、事务创建、禁止自聊 |
| 群聊 | 创建、资料冲突检查、权限、成员生命周期 | 创建、改名、增减成员、退群、转让群主、解散 |
| 历史权限 | 入群前、离开期间不可补拉；重入不恢复缺口 | 多段 `[joined_seq,left_seq)`；旧成员资料在离开时冻结 |
| 消息接受 | 服务端排序；ACK 丢失不重复；跨账号不能伪造发送者 | 全局 message_uuid、发送者＋client_message_id 双重唯一；事务序号 |
| 幂等 | 同操作原字节重试；刷新后可恢复；冲突不执行 | 复用全局 operation_id 与加密恢复记录，10 分钟窗口 |
| 离线／多设备 | 不能依赖在线连接保证送达 | 每账号持久事件流、签名游标、HTTP 增量、固定快照 |
| 实时 | 有界连接、撤销后断开、重连补偿 | 二进制 WebSocket 提示；HTTP 获取权威实体 |
| 历史 | 固定上界、覆盖区间、权限版本、响应限额 | 逆序分页，空页也可推进；边界变化要求重开分页 |
| 已读／送达 | 多设备 max 合并；已读隐含送达 | 用户级水位、独立版本摘要；客户端显式确认覆盖范围 |
| 未读 | 自发、撤回不计；不能用 seq 差值 | 按权限和正文状态计算精确数量 |
| 群回执 | 分母固定在发送时；快照分页不能混合版本 | 固定受众、独立回执版本、发送者可查询固定明细快照 |
| 撤回 | 权限与时限；终态；旧推送／重试不可复活 | 发送者 120 秒；消息引用式事件与幂等结果；正文清空 |
| 删除与清空 | 区分本机删除、全端撤回、群解散 | 本机删除／清空仍属客户端行为，不增加远程删对方消息 API |
| 加密与安全 | 敏感正文不明文持久化；事务一致；账号隔离 | 复用 AES-GCM、用途及记录 AAD、共享 gate、单实例锁 |
| 验收 | 真实数据库、异常与并发、网络联调 | Swift Testing＋隔离回环 TCP／WebSocket smoke，见验证记录 |

群管理采用群主直接加入已存在用户，普通成员仅可主动退出；群主须先转让或解散。此策略仅用于当前虚构账号联调。邀请审批、拉黑、举报和滥用治理是开放真实用户之前需要重新评审的产品能力，不能将此策略直接搬到公开服务。

## 业务不变量

1. 消息、序号、接收范围、事件与操作结果同一事务提交。所有账号与 IM 访问共享一个 gate；当前不支持多个实例并行写入。
2. 普通消息 UUID 原样代表同一身份（返回 UUID 规范化为小写），消息位置接受后不变。群资料更新、阅读、撤回不占用新消息序号。
3. 事件位置只在本账号事件流内有意义；不能拿对方游标或消息序号当作同步游标。
4. 消息版本、会话资料版本、权限边界版本、阅读／回执版本分别合并。`latest_seq` 按边界单调推进，不能只按会话资料版本丢弃较新的阅读摘要。
5. 同一事件可以再次读取到更新的实体版本。事件是刷新通知而非不可变正文日志；撤回后重读早期事件也只能得到撤回占位。客户端只接受更高实体版本。
6. 送达／阅读请求表示调用设备已经覆盖授权范围内的所有较早消息，不能将乱序收到的最大序号作为覆盖水位。服务端验证权限上界，但不证明用户实际阅读。
7. 退出账号撤销的是认证会话；退群关闭的是群成员区间。退出账号不删除群关系或消息。群解散禁止新消息，授权历史继续可查。
8. 旧成员仍可访问原授权区间及自己的历史回执；离开后的群资料不再对其更新。重入后恢复当前群资料，离开期间正文仍不可见。

## 同步策略

实时连接只发送 `IMSyncHint`。客户端以自己已提交的 checkpoint 拉取 `events`，按事件刷新会话／消息，在本地事务成功后保存 next_cursor；绝不直接保存提示中的 latest_cursor。断网或提示丢失时，同一 HTTP 增量流程补偿，后台轮询亦可使用。

首次设备可从空游标重放完整流，也可先建立会话快照，完成固定分页后用 baseline_cursor 补增量并拉各会话历史。快照包括离开／解散关系，不以“某页没出现”推断删除。暂不保留期清理事件，因此当前正常游标不因时间过期；epoch 失配返回 `CURSOR_EXPIRED` 后主动请求空 token 快照。数据库恢复或人工修改 epoch 的运维流程尚未提供，不能清空事件表来模拟压缩。

`receipt`／`read` 事件通知会话级回执变化。客户端以会话摘要推进自己的阅读状态，并对需要展示的消息重新读取历史或回执明细；旧明细快照保持原版本，新的摘要不能混用旧明细。文本正文不支持编辑、引用、回复、reaction 或自定义 payload，本轮拒绝这些类型而不透传未校验内容。

## 媒体后台扩展

已按独立确认的媒体计划实现图片、动图、视频、语音、文件、Live Photo 和有序媒体组后台。支持固定分块上传、持久化处理任务、原件完整性验证、原生预览、短期授权 Range 下载和引用回收；客户端只同步协议。详细范围、限制和错误见 [媒体契约](media-contract.md)，磁盘认证格式见 [媒体存储](media-storage.md)，实际执行证据见 [验证记录](validation.md)。

病毒扫描、内容审核、对象存储、Linux、生产部署和 iOS 上传／缓存／UI 接入仍未实施；不能把字段加密或媒体加密描述为端到端加密。

## 后续完整产品需求与上线门槛

| 能力 | 后续工作 |
| --- | --- |
| 真实网络 | HTTPS／WSS、证书、代理可信边界、生产鉴权与持久限流 |
| 群治理 | 邀请／审批、管理员、禁言、群公告、退出再邀请策略、群容量与滥用控制 |
| 用户关系 | 联系人、申请与接受、拉黑、举报、账号注销后的消息与资料规则 |
| 消息扩展 | 客户端媒体接入、编辑与版本、表情回应、系统消息类型与客户端升级策略 |
| 后台通知 | APNs token 生命周期、静默补偿、通知隐私、免打扰、撤回通知处理 |
| 多节点 | PostgreSQL 等共享权威存储、并发序号、分布式限流、事件投递队列、故障恢复与背压 |
| 保留与删除 | 事件截断及 epoch 管理、快照恢复、账号删除、加密备份、密钥轮换与销毁 |
| 搜索与审计 | 授权范围搜索、敏感审计最小化、脱敏指标、容量／延迟／恢复 SLO |
| 客户端接入 | 加密本地库、outbox、游标事务、状态连续性、四语言／RTL 与 UI 验收 |

当前上限是开发保护阈值：每账号最多 500 个历史会话关系；每群最多 100 个历史不同成员、每成员最多 100 段加入记录；每会话最多 100000 条消息；同账号最多 16 个有效固定快照（10 分钟），固定快照原始数据最多 16 MiB。未做容量压测；达到阈值返回明确错误，不自动删记录或降级权限。未读读取尚需扫描授权范围内的消息，生产前需新增经过验收的计数投影和索引，不能视作大规模 IM 架构。

传输 API 的选择参考 [Vapor WebSocket 文档](https://docs.vapor.codes/advanced/websockets/)；具体实现与锁定依赖源码核对。实现契约见 [IM 网络契约](im-contract.md)，安全边界见 [security.md](security.md)。

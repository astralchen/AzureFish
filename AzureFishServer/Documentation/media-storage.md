# 本机媒体密文格式与故障边界

格式版本 1，范围仅本机虚构数据。实现为 `MediaBlobStore` 边界及 `LocalMediaBlobStore`；当前服务组合本机实现，未来存储适配器需同时提供初始化、临时工作空间、容量与恢复能力。

## 密钥和 AAD

每个 resource_id 独立生成随机 256 位 AES 密钥。使用现有主密钥，以环境为 HKDF-SHA256 salt、`media-key-wrap-v1` 为 info 派生专用包装密钥；与账号字段 AES、HMAC 用途分离。资源密钥以 AES-GCM 包装，AAD 绑定 `media-key:`＋资源 UUID。包装值保存在 media_resources.wrapped_key；不得从 ID、文件名或密码生成资源密钥。

分块与清单使用 Swift Crypto AES.GCM 的随机 nonce、认证标签和 combined 表示。AAD 是下列 UTF-8 字段逐项编码，每项前置 8 字节大端无符号长度，避免分隔歧义：

1. `azurefish-media`
2. `1`
3. 环境 ID
4. 上传者 UUID（Swift 标准大写 UUID 文本）
5. 资源 UUID（同上）
6. 用途角色：original／paired_video／thumbnail／cover
7. 数据用途：chunk／manifest
8. 分块编号十进制（manifest 固定 0）
9. 本块明文长度十进制（manifest 为资源总明文长度）

文件夹只用小写资源 UUID；文件只用服务端随机 UUID 和 `.bin`／`.manifest` 后缀。用户文件名、SHA-256、MIME、媒体尺寸、波形和处理失败详情均进入既有带记录上下文的字段加密。表中状态、关系、分块编号、容量预留、generation 与时间仍是可见元数据。

## 分块、清单和随机读取

每个明文块最大 4 MiB，AES-GCM combined 多 28 字节。数据库中分块描述符包含编号、长度、SHA-256 和随机文件名，整体加密且绑定分块记录 UUID。清单是加密 JSON，包含 version、bytes、sha256 和有序 chunks；只有完整重读每块、验证其标签／摘要／编号／长度及整件 SHA-256 后才写入。

读取先验证资源包装密钥和清单认证，再按 Range 涉及的块独立解密验证；每块必须在完整认证成功后交给输出。清单固定块顺序和总长度，替换资源、跨上传者替换、改用途、重排和截断均不能生成可接受明文。传输内存以有限并发的分块为单位，不读入整个视频／文件。线程池 IO 及完整散列的每块使用 autoreleasepool，及时释放 Foundation 桥接对象。

密文写入不可预测的新文件（O_EXCL、O_NOFOLLOW、0600），写完并同步文件及父目录后才提交数据库描述符；旧文件不会被同名覆盖。上传事务失败即时移除新写分块；崩溃残留及未提交清单由启动对账清理。资源目录与工作目录 0700，拒绝不符的目录类型／权限。文件读取 O_NOFOLLOW，并检查普通文件和大小上限。

## 处理与回收

工作进程只接收本次任务路径，临时原件按块还原到独立受限目录。父工作目录排除备份；worker 使用 0077 umask，不输出文件名、正文或底层解码异常。主服务超时或任务取消时终止进程并清理工作目录；启动首先清理旧工作目录。预览通过新资源密钥加密后才提交 ready。普通文件完全不交给媒体解析器。

未完成任务和回收任务都持久化。启动将中断 processing 重新排队，并清理数据库无引用的资源目录／文件。回收先更改状态／generation 拒绝新访问；现有请求每块重验，回收等待其租约结束。随后删除资源文件，最后在事务内清除包装密钥、分块、私密描述与配额。删除失败时不会提前丢钥；事务失败可重新删除不存在的文件并重试密钥清理。

缺失／错误包装密钥或密文认证失败必须停止消费原件，不创建替代密钥或空文件。数据库字段解密失败也不恢复为默认空状态。服务端字段加密与媒体加密均不代表端到端加密，也不能替代客户端 GRDB／SQLCipher、Keychain、账号隔离和临时明文清理。

## 验证要求

[验证记录](validation.md) 单独列出本次执行结果。必须覆盖认证篡改、跨资源／角色／上传者替换、乱序与截断、错钥与缺钥、提交失败孤儿、进程崩溃／超时、启动清理、配额释放和大文件 Range。物理磁盘满、断电后文件系统持久性、密钥轮换、备份恢复和生产部署仍需在对应环境专项验证；不能用本机单元测试替代。

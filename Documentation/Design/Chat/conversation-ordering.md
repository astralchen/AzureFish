# 会话排序与显示

2026-09-28。实现入口：`ChatRuntime`、`ConversationListViewController`、`ConversationListState`、`AccountChatDraftStore`。

## 排序规则

1. 先筛选本机已出现且未隐藏的会话；隐藏不会删除关系、草稿、发送队列或置顶设置。
2. 置顶在普通会话之前。两组内部均按 `activityAt` 降序，相同时间按会话 ID 升序。
3. 活动时间来自可访问的非系统消息、首次入本地发送队列的文字／媒体。接收消息使用服务端毫秒时间，入队使用本机时间；此轮不调整时钟偏移或增加跨设备排序时间协议。取最大值，旧增量、普通历史回填不会把排序时间倒退。
4. 重试状态、传输进度、回执、已读、手动未读、免打扰、资料／备注变化不改变活动时间。置顶只改变分组，不生成新活动时间。
5. 清空历史、删除单条消息、隐藏、草稿编辑不重置或增加消息活动时间。仅有草稿、从未有消息的会话使用 0，同时间仍按稳定 ID 排序。
6. 系统好友提示不单独使会话出现；消息撤回不解除隐藏。会话隐藏后，新的非撤回内容、主动发送或修改非空草稿可恢复可见性。仅打开资料或会话不恢复。

上述是 AzureFish 明确采用的规则。微信未公开完整比较器；草稿是否抬高排名、清除后是否回到旧排名、新置顶之间的细节尚未按当前目标版本实测，因此不声称逐项复刻微信。

## 草稿

- 摘要优先显示本机未发送草稿，标明“[草稿]”。有文字时显示前 256 个字符（不截断或改写保存内容）；纯附件显示“未发送的附件”。文字、富文本、文档、媒体组和语音预览均使用现有加密草稿。
- 保存非空且文字或附件身份／顺序变化的草稿时，在同一 SQLCipher 事务恢复会话可见性；重复保存、编辑器修订号变化、临时媒体 URL 变化不恢复已隐藏会话。清空草稿后已恢复的会话仍显示。
- 草稿与列表可见性、折叠偏好在同一读取事务取快照；更新后刷新同账号同环境的本机场景。异步消息摘要按渲染代次与账号存储身份保护，不能覆盖新草稿。
- 原有库直接读取草稿和 v1 富媒体清单，无需清库或新增表。读取旧草稿不产生用户编辑副作用。发送仍沿用原有原子入队并删除草稿的事务。
- 草稿不是消息，不发送给服务端或联系人，也不产生未读。备注优先名称刷新与草稿摘要互相独立。

## 折叠置顶

- 有置顶聊天就提供手动折叠入口，不猜测微信不同版本的自动折叠数量阈值。默认展开。
- 折叠会收起全部置顶行，按钮继续显示置顶聊天数和含未读／手动未读的聊天数。新增消息更新统计，不擅自展开。展开后沿用原排序。
- 折叠偏好写入当前账号的加密 `meta.list-pinned-collapsed`，同账号本机窗口及时更新；普通退出保留。保存成功后才刷新，不重复提交。
- 搜索临时显示所有匹配的可见会话；不修改折叠偏好，不把隐藏会话带入结果。取消搜索后恢复折叠。
- 收起后的行不计入当前展示行，但内容／空状态判断依据真实匹配会话数；全部置顶被收起时不显示“暂无聊天”。
- 置顶、免打扰、草稿与折叠目前均为本机账号数据，不承诺跨设备同步。名字按备注优先显示；服务端昵称更新不会重新排序。

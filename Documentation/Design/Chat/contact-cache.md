# 通讯录本地优先缓存

2026-09-29。客户端实施范围：通讯录、好友申请、黑名单、备注、公共资料及头像；参考打开即显示、后台更新的使用体验，不声明复现微信内部实现。网络契约、关系规则及登录恢复边界保持不变。

## 读取与同步

账号 SQLCipher 库打开后，`ChatRuntime` 先用同一次数据库读取恢复通讯录和检查点并发布，再恢复传输和启动同步。通讯录的本地恢复状态与会话列表就绪状态分开，避免提前发布导致会话列表短暂显示为空。联系人同步入库后先通知页面，随后才检查会话历史。保留现有启动、前台、WebSocket 提示、定时补拉和下拉刷新，不增加轮询。

已有内容在离线和刷新失败时继续显示；无数据且首次快照未完成显示加载或失败，完成后的空通讯录与搜索无结果分别呈现。资料页立即使用本地数据，后台按环境、账号及联系人合并并发校验；保存后发布权威结果。新增离线修改不排队，现有待确认操作继续按原字节对账。

## 信息更新对缓存的影响

| 更新 | 缓存与界面行为 |
| --- | --- |
| 昵称 | 按公共资料版本合并，更新显示名、搜索、分组和会话标题；个人备注仍优先 |
| 备注、关系、申请、拉黑 | 按关系版本独立合并，更新列表归属、搜索、数量和有效操作，不覆盖较新的公共资料 |
| 头像资源 ID | 新 ID 独立读取内存、磁盘或网络；旧任务完成也不能回填已切换身份的视图 |
| 恢复默认头像 | 新资料版本的空 ID 生效后显示默认图，不回退到旧版本密文 |
| 账号注销标记 | 最新公共资料的删除标记优先，名称使用注销提示，头像不再显示旧资源 |
| 旧查询或旧快照晚到 | 分别比较关系和资料版本，不恢复旧备注、已删除关系、旧头像或旧昵称 |
| 语言／主题变化 | 更新本地显示与排序，不重新下载头像、不重建业务会话 |

通讯录、资料页和会话列表使用同一账号头像加载服务。会话列表从运行时合并后的最新公共资料取得头像身份，不直接沿用会话成员内的旧资料。

## 头像内存、磁盘及生命周期

头像身份包含环境、登录账号、目标用户和资源 ID。同一身份的并发消费者共享下载与解码；取消单个视图不取消其他消费者的任务。内存命中同步显示，磁盘读取、认证解密、加密写入和图片解码在后台执行。

已解码图片按实际像素字节成本采用 16 MiB 内存预算，超预算单图不常驻缓存，内存警告释放缓存引用。可见视图仍可能持有图片，该预算不是全应用内存上限。

通讯录资料及**所有已下载头像密文长期保留**，包含旧资源版本；不设置磁盘 TTL、不按容量淘汰、不新增手动清理入口。磁盘占用随已下载资源增长。删除联系人或拉黑不删除历史资料和头像密文；展示始终由当前权威关系及资料决定。

普通退出和切账号使共享加载服务失效、清空明文图片引用、取消任务，保留磁盘与密钥。账号文件删除前必须等待共享任务及已开始的磁盘访问完成，再按文件、密钥的顺序清理，避免删除后被迟到写入重建。缺失／错误密钥和认证失败原样报错，不按未命中下载覆盖。

保持已有 `AccountAvatars` 目录、Keychain 标识及 AES-GCM 格式，无需迁移清库。网络仍禁用 URLCache 持久缓存；没有新增 ETag／304 协议。安全与账号生命周期以[安全规范](../../Security/README.md)及[数据库生命周期](../../Database/lifecycle-and-migration.md)为准。

# 通讯录与好友管理

2026-09-28。未发版阶段统一采用单向联系人模型。本文替代早期通讯录设计中的“双向删除”和资料页双主按钮；既有 Figma／PNG 为历史参考，不代表本轮运行截图。协议唯一来源为服务端 `Protos/azurefish.proto`。

## 页面与交互

通讯录提供搜索、新的朋友、分组索引和联系人数量。2026-09-29 的 ListKit 触摸索引增强见[实现与验证](contact-index.md)。备注优先于公共昵称；搜索匹配备注和昵称，分组和排序统一使用显示名称的中文拼音，不随应用语言变化；索引按 A–Z 排列，非字母首字符归入末尾的 `#`，同一排序键以用户 ID 稳定排序。自己拉黑的联系人只在黑名单显示。空通讯录、首次同步、同步失败、搜索无结果和离线缓存分开呈现，空状态不是可点击的联系人。2026-09-29 本地优先展示、信息更新及头像共享缓存见[缓存实现与验证](contact-cache.md)。

新的朋友每人保留最近一次申请：留言、日期、待处理／已接受／已拒绝／已取消。只有当前账号收到且可接受的申请展示行内接受按钮。查看页面不会清除待处理数量。资料页展示备注入口、主要业务动作及管理入口，管理页单独承载删除和拉黑确认。

添加流程为完整账号查询、核对资料、编辑留言和提交。备注最多 64 个 Swift Character，留言最多 200 个，允许留空；与服务端使用相同控制字符规则。编辑页面失败保留输入，过期查询不能触发导航。备注只属于当前账号，同账号多设备同步，不改写公共昵称；在会话列表、私聊标题、群成员及发送者名称中统一显示。昵称更新在服务端同事务推进相关投影，在线设备由现有 WebSocket 提示触发 HTTP 补拉，断线后补拉对账。关系版本与资料版本独立合并，旧响应不覆盖新昵称。同账号自身资料版本变化也会触发 `/me` 刷新；当前页面订阅更新，无需重新进入。

黑名单入口：我 → 应用设置 → 隐私 → 黑名单。宽屏通讯录使用系统双栏，regular 且容器宽度至少 840 pt 时展开，否则单栏；列表、资料及编辑控制器随系统容器保留。iOS 15～25 使用原生非玻璃控件，26+ 使用系统外观。四语言、主题和 RTL 沿用既有协调机制。

## 关系规则

- 删除仅清除自己对对方的联系人保留标记，对方条目保留。双方暂停新的私聊和相互邀请入群，历史、草稿、既有群聊和备注保留。
- 自己删除、对方仍保留时可直接恢复；双方都删除时重新申请。存在待处理申请时优先处理该申请。直接恢复不新增好友通过系统消息，接受申请沿用同事务双向系统提示。
- 拉黑保留关系，禁止双方新私聊、好友申请及相互邀请入群，结束待处理申请；不影响既有群聊和历史权限。
- 解除拉黑只取消自己的限制，不恢复已删除关系或已结束申请。对方仍拉黑时权限继续受限。
- 删除与拉黑不产生通知或系统聊天消息。服务端只返回本人私有设置及有效操作集合，不公开对方备注或黑名单原始字段。
- 服务端已受理消息维持原结果；未受理发送重新检查当前权限。失败的 outbox 不因关系恢复自动重新发送，由用户主动重试。

好友详情的“发消息”先使用本地缓存导航；没有私聊历史也直接打开空聊天页，首次实际发送才解析服务端会话。离线可打开页面和编辑草稿，发送权限仍由当前认证与关系状态决定。实现与验证见[联系人本地打开聊天](local-direct-navigation.md)。

## 权威数据、恢复与兼容

服务端的双方设置保存在原关系实体的加密 payload，各自具有投影版本。申请独立保存 ID、方向、状态、留言和时间。备注变更只产生本账号事件；影响权限的关系变更产生双方同步事件。快照和增量继续与实体、游标同事务入客户端 SQLCipher 库。

2026-09-30 客户端改用 `account-storage-v1`：用户资料、本人关系、申请和可用动作分别存于 `user_profile`、`contact_relationship`、`contact_request`、`contact_available_action`。不确定写操作使用 `contact_pending_operation`，保留原始 Protobuf 字节并列化业务字段；重试不重新生成请求。旧开发库明确拒绝打开，详情见[账号存储生命周期](../../Database/lifecycle-and-migration.md)。

数据迁移将旧好友变为双方保留，旧双向删除变为双方移除，保留最近申请方向和结果；为已有账号生成同步事件。客户端旧缓存可读取但不启用新写入，补完整快照后采用权威投影。无清库、替换密钥或重建空库路径。服务端启动先验证原密钥，再迁移。

联系人修改先保存操作 ID 和 Protobuf 原字节到账号加密库。响应丢失时重放同一次操作；版本冲突／恢复窗口到期先读取当前状态，保留输入并要求重新确认。退出和账号切换阻止迟到结果发布。离线编辑不会伪造关系成功，也不排队生成新的联系人操作。

客户端、协议和服务端共同升级；写请求声明 semantics_version=2，并在当前关系响应确认能力。旧写请求返回 CONTACT_CLIENT_UPDATE_REQUIRED；不继续维护旧双向删除行为。

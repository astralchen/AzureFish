# 多设备自适应 UI／UX 规范

> **状态：设计阶段，尚未接入应用。** 更新日期：2026-09-24。本文只定义布局与交互规则，没有改动页面。返回 [项目入口](../../README.md)。

## 1. 全局原则与适用范围

沿用 UIKit＋QuickLayoutKit、系统导航、ListKit 列表与同文件 DEBUG #Preview。认证最低支持 iOS 15；聊天现有 iOS 26+ 路由不扩大为认证的最低版本。

系统外观边界统一如下，适用于 iPhone、iPad 和 iPhone Duo：

| 系统版本 | 浅色模式 | 深色模式 |
| --- | --- | --- |
| iOS／iPadOS 15～25 | 原生**非液态玻璃**浅色外观 | 原生**非液态玻璃**深色外观 |
| iOS／iPadOS 26 及以上 | 系统 **Liquid Glass（液态玻璃）** 浅色外观 | 系统 **Liquid Glass（液态玻璃）** 深色外观 |
| iPhone Duo，iOS 27.1 及以上 | 液态玻璃浅色＋内外屏、安全区域与 reserved regions 适配 | 液态玻璃深色＋内外屏、安全区域与 reserved regions 适配 |

主题与系统外观是独立维度：切换深浅色不会使旧系统出现 Liquid Glass。iOS 26 以下使用对应系统的原生导航栏、标签栏、分组列表、语义颜色和常规背景，不仿制液态玻璃；iOS 26+ 优先使用系统导航与控件提供的材质。

登录、个人中心和账号安全共享业务状态与自适应布局，按系统版本选择外观；外观分支不改变功能、输入状态或导航连续性。Liquid Glass 专用 API 按实际 SDK 设置准确的 availability 检查，不进入 iOS 26 以下路径；Duo 专用能力另按 iOS 27.1 检查，不能混用两个版本边界。“降低透明度”“增强对比度”开启时尊重系统呈现，不强制维持透明玻璃效果。

详细页面见 [认证 UI／UX](../Authentication/ui-ux.md)，语言见 [国际化规范](../Internationalization/README.md)，证据要求见 [验证矩阵](../Security/validation.md)。本规范用于未来全应用，当前只细化登录、个人中心和账号安全，不新增会话列表、群管理或完整聊天设计。

## 2. 根据窗口选择结构

可用宽度定义为当前内容容器 bounds.width 减去该容器实际左右 safeAreaInsets；不使用 UIScreen.main、设备型号或应用启动时缓存的屏幕宽度。对已处在 safe area 内的容器，不重复扣除父级 inset。局部 reserved region 仅影响与其相交的内容，不一律从整页宽度扣除。

| 布局 | 进入条件 | 内容规则 |
| --- | --- | --- |
| 紧凑导航 | horizontal size class 非 regular，或可用宽度小于 840 pt | 单列导航，列表选项 push 详情 |
| 宽屏认证 | 欢迎、注册、登录、资料完善在任何宽窗口 | 单列表单居中，内容宽度不超过 440 pt；边距至少 20 pt，狭窄时按剩余宽度缩小 |
| 宽屏个人中心 | horizontal size class 为 regular 且可用宽度至少 840 pt | 系统 UISplitViewController 双列，主列首选 320 pt、范围 280～360 pt；详情使用剩余空间 |
| 宽屏编辑详情 | 双列中的表单／账号安全详情 | 正文限制在最大 600 pt；安全确认与密码输入表单最大 440 pt，可滚动 |

840 pt 按当前“我”内容容器度量，不是按整个设备或另一 tab 的宽度。系统 tab／侧边栏若占用空间，以实际子容器宽度重新判断。横向 regular 但不足 840 pt 时仍为单列。辅助功能字体不改变业务导航，只让行自然增高、正文换行和页面滚动。

主界面保留系统 tab：聊天／我。个人中心 tab 的自适应容器在单列／双列间保存同一选择与详情状态；宽屏首次展示个人资料概览，未选项显示明确概览内容。折叠时优先显示当前详情，并保留返回主列表路径；展开时在左列恢复选择。尺寸变化不自动跳回根页面。

## 3. iPhone、iPad、iPhone Duo

普通 iPhone 验证小屏、横屏及安全区域；iPad 验证全屏、分屏、窗口连续缩放、横竖屏、外接键盘和触控板。菜单／action sheet／popover 必须绑定发起控件及其当前 windowScene，旋转后更新锚点，不寻找 connectedScenes.first。

iPhone Duo 覆盖外屏、内屏、展开／收起及可用的设备姿态。普通适配依赖窗口、trait 和安全区域；不以 phone idiom 假定一定窄屏，也不使用猜测的屏幕尺寸或铰链数值。[Apple Duo 开发入口](https://developer.apple.com/iphone-duo/)

iOS 27.1 下通过官方 reserved regions 能力保护按钮、输入、正文、头像交互区，使用目标 view 坐标下的区域并在其变化时更新。背景可以按视觉设计延伸。系统 toolbar／tab bar 采用系统布局，不叠加自绘固定底栏；避免将局部摄像区域当作整页边距。[Apple 自适应布局说明](https://developer.apple.com/videos/play/tech-talks/111463/)

代码阶段用包含 iOS 27.1 SDK 的 Xcode 编译增强路径；旧系统不引用不可用类型。当前已核对 /Applications/Xcode.app 包含 iOS 27.1 SDK，但全局 xcode-select 指向另一安装；后续测试显式选择 DEVELOPER_DIR，不在文档任务中切换系统配置。模拟器 runtime、可用姿态与真实设备必须另行验证，不以 SDK 文件存在证明运行通过。

## 4. 转换中的状态与几何

| 状态 | 所有者／恢复规则 |
| --- | --- |
| 当前账号与认证请求 | SessionCoordinator，与布局容器生命周期分离；不重建 session 或重复登录 |
| 导航选项与详情 | 语义 route／selection ID；单列与双列消费同一状态 |
| 昵称、简介、密码输入 | 页面工作状态，尺寸变化不重新初始化；密码仅短期内存，不写恢复文件 |
| 焦点与键盘 | 保留字段 ID、选择范围，布局完成后按需恢复；不反复 resign/become 导致键盘闪动 |
| 头像上传与授权 | 流程协调器持有 operation_id；视图重排仅重新绑定展示，不再次发起请求或系统授权 |
| 列表与表单位置 | 用稳定 item／字段 ID＋可见偏移恢复，避免只复用旧 contentOffset |
| 弹层 | 尽量保持系统呈现；锚点消失时安全收起并保留输入，不在新几何下使用旧坐标 |

只在当前布局代次的容器、安全区域、键盘和内容测量完成后恢复可见锚点；丢弃旧代次测量回调。QuickLayout 滚动内容应结合 adjustedContentInset，避免重复左右 margin 导致页面可横向拖出空白。过渡中不强制滚到顶部或消息底部。

首帧必须已使用当前尺寸和语言方向；“最终一帧正确”不等于通过。旋转／折叠／语言切换期间，网络迟到响应仍受账号 generation 与资料版本保护。

## 5. 视觉、输入和无障碍

系统语义颜色、Dynamic Type、SF Symbols 与原生 Apple 按钮为基线；触控目标至少 44×44 pt。正文、错误和按钮可换行，首屏容不下时滚动；不能缩小字体来掩盖溢出。表单分组的标签、帮助、错误按稳定顺序呈现，loading 不改变按钮外框高度。

VoiceOver 顺序随语义而非屏幕物理左右决定；双列有明确标题与选择状态。键盘焦点顺序支持 Tab／Shift-Tab，Return 根据字段提交或移动；辅助功能焦点在容器转换后回到同一操作或合理标题，不落在消失视图。警告／成功用适度播报，用户取消系统授权不作为错误。

RTL 使用 leading／trailing，系统导航负责镜像；不再手动交换物理左右叠加一次镜像。分别为 iOS 26 以下非液态玻璃、iOS 26+ 液态玻璃及 iOS 27.1 Duo 适配提供验证样例，覆盖深浅色、大字体、四语言、“降低透明度”和“增强对比度”。同文件预览不弹真实授权或访问网络，不能替代对应系统上的实际页面验证。

## 6. 主题偏好与实时切换

应用提供“跟随系统、浅色、深色”，默认跟随系统。未登录欢迎页提供外观菜单；已登录入口为“我 → 应用设置 → 外观”。两处读取同一偏好，当前选择显示勾选及可被 VoiceOver 识别的选中状态；跟随系统时即使当前呈现深色，仍勾选“跟随系统”，不勾选“深色”。

| 偏好值 | 菜单语义 | 生效规则 |
| --- | --- | --- |
| system | 跟随系统 | 不固定窗口主题，随各窗口系统环境变化解析实际浅色／深色 |
| light | 浅色 | 所有应用窗口保持浅色，不被系统深色切换覆盖 |
| dark | 深色 | 所有应用窗口保持深色，不被系统浅色切换覆盖 |

偏好保存到本机 UserDefaults 的独立键 `azurefish.appearance.preference`，只允许 system／light／dark，缺失或无效值回退 system。该值不是敏感账号数据，不进入 Keychain、账号数据库或网络协议；退出、切账号及清除某账号本地数据不重置主题。语言偏好使用自己的键，两者互不覆盖。

启动和新建窗口在首个页面显示前读取并应用偏好，避免先亮后暗；现有窗口立即同步更新，后台窗口在再次显示前同步。system 表示所有窗口遵守同一“跟随系统”策略，不把某个窗口解析出的具体颜色写回偏好或强制给其他窗口。恢复 system 后解除手动固定，立即按当前系统环境更新。

切换只更新外观，不重建 root 或业务协调器，不返回首页，不清空表单、焦点、选择范围、导航、滚动位置或上传状态，不重发认证／保存请求。系统授权、相册和权限界面遵循平台支持的呈现行为，不用自绘替代，也不保证正在展示的系统界面可被应用强制即时换色。

动态颜色在当前 trait 环境中解析；自定义绘制、缓存的图标／背景以及 layer 颜色在外观变化时刷新，不能只在首次创建时保存一份浅色结果。系统控件的默认适配优先，业务照片与视频不反色、不重新编码。

### 深浅色视觉和状态规范

| 元素／状态 | 两种模式共同要求 |
| --- | --- |
| 页面、分组容器与分隔线 | 使用 systemBackground／systemGroupedBackground、secondarySystemGroupedBackground、separator 等对应语义色，区分内容层级；不以固定白／黑或简单反色实现主题 |
| 正文、帮助与占位 | 使用 label／secondaryLabel／placeholderText 等语义色；次级文字仍可读，不用降低整页透明度替代层次 |
| 按钮、禁用与焦点 | 主操作使用系统 tint 与按钮状态；禁用由状态与语义样式共同表达，焦点／选中可辨；保持触控尺寸及标签 |
| 图标、默认头像与品牌 | 检查两种背景下的轮廓和辨识度；必要时提供浅深色资源变体，SF Symbols 优先跟随语义 tint；用户头像、照片、视频原样展示 |
| 加载与空状态 | 使用适配当前主题的进度指示、说明及占位图；加载保持布局尺寸，不闪现另一主题底色 |
| 字段错误、离线与重试 | 同时使用语义颜色、图标和可读文本；不只靠红色区分，浅深色下重试入口均清楚 |
| 删除确认与危险操作 | 保持系统 destructive 语义和完整影响说明；不以大面积固定红色背景破坏对比 |
| 液态玻璃与辅助功能 | iOS 26+ 使用系统材质，响应“降低透明度”“增强对比度”；iOS 26 以下保持原生非液态玻璃，不能手绘玻璃强行统一 |

主题选项、入口名称、选中状态和切换结果的无障碍描述覆盖四语言，参见国际化规范。验收包括主题、语言和窗口变化连续发生，不把主题变化解释成新的登录或页面加载。

## 7. 未来聊天接入要求

聊天后续保留稳定消息 ID、阅读锚点、输入草稿、附件选择及媒体播放对象；尺寸变化不重发消息，不丢失多选，不自动将阅读位置移到底部。数据库观察与 cell 重用不得替换菜单目标身份。具体聊天双列结构、群资料与媒体浏览页面在 IM 阶段另立设计，不借本轮认证规范宣称已适配。

验证需分别覆盖首次进入即滚动、尺寸变化后滚动和语言切换，不只测试折叠动作。实际测试结果、系统版本和任何环境跳过项记录于 [验证矩阵](../Security/validation.md)。

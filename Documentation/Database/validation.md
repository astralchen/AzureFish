# 开发验证与验收方案

> **状态：设计阶段，尚未接入应用。** 本次只交付 Markdown 开发文档。以下数据库、应用及服务端场景均为后续实施验收要求；不能据此宣称已实现或已通过。返回 [文档入口](README.md)。

## 1. 开发顺序与完成条件

| 阶段 | 后续开发工作 | 完成条件 |
| --- | --- | --- |
| A：存储底座 | 先验证 GRDB＋SQLCipher／FTS／密钥存取，再接入账号隔离、迁移、连接池、字段模型和约束 | iOS 15 存储能力验证；空库和升级库测试；隔离与错误状态明确 |
| B：本地消息与资源 | Repository、媒体所有权、草稿迁移、持久任务 | 重启恢复消息／附件；草稿版本冲突正确；页面销毁不删除消息资源 |
| C：同步闭环 | 模拟服务端、幂等发送、增量／历史、删除撤回、未读 | 重放、乱序、游标失效及崩溃注入矩阵通过 |
| D：群回执与搜索 | 群成员版本、统计与明细、搜索分词和索引维护 | 成员变化不污染历史回执；删除内容不可搜；多语言检索样例通过 |
| E：UI 与容量 | 现有 ChatViewModel 接入、真实列表回归、百万消息测量 | 首帧和滚动锚点无回退，报告设备／数据／耗时分布及限制 |

每阶段先完成可替换模拟依赖，真实账号、后端和权限尚未具备时标注“被环境阻塞”或“未执行”，不得把模拟通过等同于真实网络通过。设计文档若因实施调整，应先同步表结构、协议和生命周期规则，再修改测试期望。

## 2. 结构与约束测试

后续生成建表及迁移实现后，在独立临时 SQLCipher 库运行，下列每项均应有明确断言，而不是只检查“建库无报错”。

| 编号 | 输入或操作 | 预期结果 |
| --- | --- | --- |
| DB-01 | 建空库、执行所有迁移、再次打开 | 表／索引／FTS 可用；迁移不重复应用；账号元数据匹配 |
| DB-02 | 同 UUID、同发送者客户端 ID、同会话服务端 ID／seq 重复插入 | 唯一约束拒绝重复；Repository 重放走原行合并 |
| DB-03 | 两个会话使用同一个 server_message_id | 允许，作用域为会话；message_uuid 仍必须全局不同 |
| DB-04 | 消息引用不存在用户／会话，附件引用不存在 asset | 外键拒绝；正常同步通过同事务占位补全 |
| DB-05 | 会话摘要或 outbox 指向另一会话消息 | 复合外键拒绝 |
| DB-06 | 同群同用户两条有效 membership | 部分唯一索引拒绝；先退出再重入成功 |
| DB-07 | 同 dedupe_key 的 outbox 或维护任务；同资源同方向传输 | 拒绝重复任务；恢复需更新原行及代次 |
| DB-08 | 非法枚举、负未读、read>delivered、人数超 expected | CHECK 拒绝 |
| DB-09 | running 缺 token 或截止时间；非 running 带活动租约 | CHECK 拒绝；业务流转仍需要额外状态机断言 |
| DB-10 | 删除仍被草稿／消息引用的 asset | 外键阻止物理删除；无引用且任务清理后才可回收 |
| DB-11 | payload 缺失、错类型 JSON、错 @ 范围、跨群 group 关联 | Repository 拒绝，明确这些并非普通 FK 已全部覆盖 |
| DB-12 | 对迁移后数据库执行 foreign_key_check、integrity_check | 无孤立关联，结构完整；另核对最低 iOS SQLite 能力 |

## 3. 行为与故障注入

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| IM-01 | 发送入队后立刻杀进程 | 消息、资源引用和 outbox 同时恢复；未提交则全不出现 |
| IM-02 | 服务端已接受但 ACK 丢失，重启后重试并收到同步回声 | 仅一条业务消息，local_id 不变，未读不重复累加 |
| IM-03 | 历史、推送和 ACK 以不同顺序到达 | 身份合并结果一致；序号与内容版本不倒退 |
| IM-04 | 撤回先于正文、旧正文重放、新版本普通正文到达 | 撤回不解除，搜索和引用不暴露原正文 |
| IM-05 | 本机删除／清空后漫游旧消息，pending 消息随后确认 | 删除记录不复活；pending 依靠 UUID tombstone 保持隐藏 |
| IM-06 | 同步事务写入一半时故障 | 所有实体、摘要和 cursor 同时回滚；重放恢复正确 |
| IM-07 | 游标失效、快照分页中断、快照 token 再次过期 | 可恢复同步；草稿、outbox、本地删除与新输入不丢失 |
| IM-08 | 退出账号后旧网络、观察和上传回调返回 | 不写入新账号；旧 generation 被拒绝 |
| IM-09 | 任务租约到期、续约与旧结果交错 | 只有当前 token 可以完成任务；服务端副作用通过幂等合并 |
| IM-10 | 草稿保存与发送并行、删除后新建后旧保存返回 | 新草稿保留，持久 draft_revision 不归零，旧写入失败 |
| IM-11 | 文件已落盘数据库未提交，或 GC 标记后杀进程 | 可回收孤立文件、可恢复 deleting；没有有效引用被删 |
| IM-12 | Live Photo 仅一半资源成功、媒体组部分导入失败 | 不把不完整 Live Photo 标 ready；保留组内顺序及可恢复项 |
| IM-13 | 磁盘满、文件保护不可用、数据库损坏、原件无远程键 | 状态可区分，不伪报成功、不自动删库，保留诊断及原数据 |
| IM-14 | 未知 content_type／payload 版本 | 保存身份与原始内容，用占位展示；分页、撤回仍有效 |

## 4. 回执、搜索和 UI 场景

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| RC-01 | 多设备阅读水位乱序同步 | 有效水位只前进，旧上报不恢复未读 |
| RC-02 | 只浏览历史、后台接收、打开预览 | 不自动上报读完最新消息 |
| RC-03 | 前台实际看见最新消息／手动全部已读 | 阅读边界和 outbox 原子更新，服务端摘要校准 |
| RC-04 | 历史不完整、序号有空洞、撤回与删除影响未读 | 不使用序号差计数；暂估可辨识，重复批次不重复扣减 |
| RC-05 | 群成员退群、重入、发送后新增成员 | 历史消息分母采用发送时接收范围 |
| RC-06 | 获取详情过程中摘要更新或 snapshot token 过期 | 旧页被拒绝，缓存不混合不同快照 |
| RC-07 | 百万消息属于多个 500 人群 | 未打开明细的消息不会生成 500 倍明细行 |
| SE-01 | “你好世界”查询“好世”、单字“你” | 中文候选与连续子串复核正确 |
| SE-02 | 相同中文字次序不同、标点隔开 | 候选可能命中，但精确复核不误报连续匹配 |
| SE-03 | 英文大小写、阿拉伯文词、组合字符、全角字符 | 与约定的规范化／整词语义一致，不改写原文 |
| SE-04 | 用户输入引号、运算符、空文本或 emoji | 不执行任意 MATCH 语法；无 token 不全表扫描 |
| SE-05 | 搜索生成期间删除或撤回、dirty 行删除后再次失效 | 全局 generation 阻止旧结果覆盖；主表回查立即过滤 |
| SE-06 | 索引重建同时持续收到消息 | 不丢新消息索引，最终消费 dirty，重建可断点恢复 |
| UI-01 | 首次展示、历史分页期间收到消息、pending 确认移动 | 消息身份与可见锚点稳定，首帧不显示错误历史排序 |
| UI-02 | 长按菜单过程中收到 ACK 或数据库观察更新 | 菜单目标仍指向原消息／原媒体项目 |
| UI-03 | 退出聊天、重新进入、杀进程重启 | 草稿和媒体可恢复，已提交原件不受页面 deinit 影响 |
| UI-04 | 简中、繁中、英文、阿拉伯语与 RTL、大字体 | 正文与语义保留，本地化系统提示在展示层生成 |

数据库及组件测试使用 Swift Testing；UI 使用 XCTest/XCUIAutomation。`#Preview` 仅用于展示模型检查，不能替代真实列表的尺寸、复用和交互验收。测试使用临时账号根目录，不清理开发者真实草稿或登录数据。

## 5. 索引与容量测量

用 EXPLAIN QUERY PLAN 验证 [关键查询](schema.md) 的预期索引。需要分别检查首页和深历史 keyset 查询、pending 合并、同时间会话分页、发送去重、任务领取、资源引用反查及 FTS 候选关联。强制指定索引不能作为“优化器自动选中”的证明；若计划出现扫描或临时排序，记录原因与实际数据规模后处理。

标准容量数据集固定为 1,000 个会话、总计 1,000,000 条消息：1 个热门会话 300,000 条、9 个各 50,000 条，其余 990 个共 250,000 条。类型分布为 70% 文本／富文本、20% 媒体、5% 文件／链接、5% 语音；至少 20 个 500 人群。媒体容量单独测量，不能用空文件测试替代真实解码和磁盘占用。

额外放入 10,000 条本地删除／撤回记录、5,000 个不同阶段任务、重复／同时间事件和历史缺口；回执详情只为 1% 的群消息填入成员明细，以接近按需缓存策略。确定性随机种子、文本长度分布、附件元数据和已读水位均保存在未来测试夹具说明中。

记录冷启动与热查询、50 次预热后至少 200 次样本的 p50／p95／最大耗时，分别报告 SQL 执行、领域映射和 UI 首帧。记录主库、WAL、FTS、媒体的体积，峰值内存、写入吞吐、后台索引积压与任务恢复时间。测量中分别施加持续同步写入和无写入负载，避免只报告空闲热缓存结果。

首轮是建立基线，不预先宣称毫秒级门槛。对同设备同数据比较新旧版本；实际产品耗时门槛在首次真机报告后单独确定，不影响本轮正确性契约。应至少验证一台能运行 iOS 15 的目标设备／环境和一台运行当前聊天 UI 的设备。模拟器性能不能代替真机性能。

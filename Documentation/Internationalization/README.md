# 四语言国际化设计

> **状态：设计阶段，尚未接入应用。** 更新日期：2026-09-24。当前代码和 String Catalog 仍只有简中、英文、阿拉伯语；本轮只设计增加繁中，不修改资源。返回 [项目入口](../../README.md)。

## 1. 语言与现有机制

复用现有 AppLocalization、LocalizationController、LocalizedStringResolver、UIWindowSceneLocalizationCoordinator 及 azurefish.locale.identifier 偏好键，不创建并行本地化服务。现有 source language 与缺失回退为英文，继续保持。

| 选项 | 语言标识 | 展示名 | 方向 |
| --- | --- | --- | --- |
| 跟随系统 | 使用框架已有 followSystem 标识 | 按当前语言翻译“跟随系统” | 按解析结果 |
| 简体中文 | zh-Hans | 简体中文 | LTR |
| 繁体中文 | zh-Hant | 繁體中文 | LTR |
| 英文 | en | English | LTR |
| 阿拉伯语 | ar | العربية | RTL |

语言选择放个人中心的应用设置，并在未登录入口提供系统菜单样式的语言入口。设置属于当前安装，不随账号切换重置，也不新增服务端语言同步接口。已有简中、英文、阿拉伯语偏好不改名；en-US 等现有内部枚举映射至英文 catalog，不能因增加繁中使旧偏好失效。

外观使用独立键 `azurefish.appearance.preference`，system／light／dark 是内部稳定值，不作为用户文案。四语言资源覆盖“外观”“跟随系统”“浅色”“深色”、当前选择、无障碍标签与选中状态；“跟随系统语言”和“跟随系统外观”在各自页面有明确上下文，无障碍描述不能混淆两者。语言变化不修改主题偏好，主题变化不修改语言；均不新增服务端同步接口。

## 2. 匹配、回退与格式化

跟随系统按 preferred languages 优先顺序寻找支持项。显式 zh-Hant／zh-Hans 优先；无 script 的中文区域 TW/HK/MO 映射繁体，CN/SG 及未指定区域中文映射简体；en-* 映射 en，ar-* 映射 ar。无支持语言才回退 en。应用手动选择使用该语言，不被前后台刷新覆盖；选回跟随系统后重新解析。

文本语言和地区格式分离：界面按应用语言，日期／数字／文件大小使用平台 Locale／FormatStyle 并保留用户地区、日历与时区偏好，不能用字符串拼接“年/月/MB”。密码与账号规范化仍遵循协议，不能使用当前显示语言的大小写转换来改变账号 HMAC 输入。

单 key 缺译在 Debug 记录缺失键并让资源检查失败；运行时回退英文且不中断页面。禁止把原始 key 作为正常 UI。繁体由独立译文维护，不运行简繁字符替换，也不把其他地区术语自动视为一致。

## 3. 资源与交付责任

Localizable.xcstrings 继续承载应用文案；InfoPlist.xcstrings 承载应用名称与权限用途。新增资源 key 使用稳定语义命名，与服务端稳定错误 code 建立明确映射；不使用整句中文作新增 key，也不批量改动旧 key。

| 资源领域 | 必须覆盖 |
| --- | --- |
| 认证 | 欢迎、登录、注册、字段规则、Apple 取消／冲突、最近确认、过期恢复 |
| 个人中心 | 昵称／简介、默认头像、独立头像生效说明、资料冲突、离线缓存 |
| 安全 | 退出、全设备退出、删除确认、外部清理中、密钥不可用与本地数据清理 |
| 通用 | 加载、空状态、重试、无法连接、权限拒绝、按钮及菜单 |
| 外观设置 | 外观入口、三种主题选项、当前偏好与选中状态、必要的无障碍说明；欢迎页菜单与设置页语义一致 |
| 无障碍 | 输入标签、密码显示／隐藏、控件值、错误关联、操作结果播报 |
| 系统用途 | 相册、麦克风、语音及未来本地网络权限；实际启用的能力逐项对应 |

用户昵称、简介和消息是用户内容，不随语言切换翻译或改写。产品名 AzureFish、账号和技术 ID 保持原义；系统 Apple 按钮、授权、相册、键盘依赖系统支持的本地化，不保证被应用内选择强制改变。

## 4. 占位符、复数与错误

整句使用带类型占位符的资源，保持各语言参数集合和类型一致，允许译文调整参数顺序。数量使用 String Catalog 复数变化；阿拉伯语覆盖 zero/one/two/few/many/other 所需类别，中文不机械复制英文单复数句式。日期和用户名不预先拼到错误句尾。

服务端 ApiError.code／FieldError.field／FieldError.code 保持现有协议。客户端映射到本地化的语义提示；未知 code 显示通用错误，并保留 request_id 用于脱敏诊断，不直接展示服务器内部描述或英文类型名。密码长度的 UI 说明需要解释 UTF-8 字节限制，不将其误译为所有语言都最多 72 个字符。

账号名、密码、URL 和用户 ID 的方向按内容语义设置；包含这些值的阿拉伯语句子使用双向隔离机制保持边界，不能在实际数据里插入方向控制符后再提交。默认系统字体提供字形与阿拉伯文连接，禁止按字母拆 UILabel 破坏连写。

## 5. 运行时切换与 RTL

继续由现有 scene coordinator 分发语言与方向快照，组件每次配置读取最新 context；不在每个按钮／cell 缓存启动时语言。页面 route、表单输入、上传 operation、认证 generation 和所选账号不随语言重置。

安全布局与方向一起更新，按一次最终快照合并连续切换，覆盖 ar→zh-Hant→en。系统导航只接受一次语义方向设置，不在已镜像的基础上再交换左右按钮。滚动位置以稳定 item／字段锚点恢复；切换后保留 first responder，并在新布局结束后恢复辅助功能焦点。

需要镜像的是导航与方向相关图标；头像、照片、视频、品牌和无方向含义图标不镜像。倒计时等数值通过格式化器显示，协议输入及签名／指纹字节仍保持不变。

主题与语言连续切换时使用各自最新偏好刷新文字、方向与语义颜色，保留选中项、输入及焦点。阿拉伯语的主题勾选位置按系统语义布局，不能以图标颜色独自表达选中；浅深色下用户照片与媒体不反色或镜像。

## 6. 验收与后续实施

先在共享语言枚举及 catalog 增加 zh-Hant，再补认证与通用资源，最后接入页面。检查现有聊天与权限资源中的 zh-Hant 覆盖，避免语言菜单可选但页面大面积回退；不借新增语言重设计聊天业务。

后续自动资源检查验证四语言完整性、占位符类型、复数和无硬编码用户文案；人工复核繁体术语及阿拉伯语语义。伪本地化用于长文本压力，不算翻译质量验收。真机按系统语言检查权限和 Apple 页面，应用内切换与系统界面分别记录。

外观菜单与设置页在四语言、RTL、大字体、浅色及深色下分别验证；系统“降低透明度”“增强对比度”组合不得降低选项与勾选辨识度。实际主题切换和对应资源仍未实现，本轮只补充规范。

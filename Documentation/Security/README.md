# 数据安全与客户端加密设计

> **状态：设计阶段，尚未接入应用。** 更新日期：2026-09-24。本轮只写文档，未集成 SQLCipher、修改网络配置或生成密钥。返回 [项目入口](../../README.md)。

## 1. 阅读与权威边界

本文定义客户端安全规则；[服务端安全设计](../../AzureFishServer/Documentation/security.md) 定义服务端字段、文件及密钥保护；[安全与跨设备验收](validation.md) 规定实施验收。[数据库字段](../Database/schema.md) 定义本地业务结构，[认证接入](../Authentication/client-integration.md) 定义会话。发生调整时同步引用方，不能各自维护不同密钥和退出策略。

目标是降低网络窃听、磁盘／备份泄露、临时文件遗留、跨账号访问与凭据重放风险。加密不代替鉴权、参数校验或资源所有权检查；服务端可以在授权业务中解密。未来 IM 端到端加密另立专项，本方案不保证抵抗已被控制的运行进程、解锁设备上的恶意代码或用户主动截图。

## 2. 数据分类与处理

| 数据 | 处理 | 禁止事项 |
| --- | --- | --- |
| 输入密码、Apple 授权码 | 短期内存与 HTTPS 请求；操作结束释放引用 | 写入日志、UserDefaults、分析事件或磁盘重试队列 |
| access／refresh 与刷新 pending operation | 原子 Keychain 凭据包 | 放业务库，拆成可能混代的多项写入 |
| 本地消息、草稿、资料、任务、FTS | 同一账号的 GRDB＋SQLCipher 数据库 | 单独建立明文搜索库／资料快照 |
| 头像、附件、持久缩略图 | 账号级 AES-GCM 加密文件 | 默认 URLCache 或第三方图片缓存落明文 |
| 数据库、媒体密钥 | Keychain，按环境与账号隔离 | 从密码、user_id、设备号推导固定密钥 |
| 明文系统预览文件 | 受保护临时目录＋租约，排除备份 | 放 Documents、共享无账号目录或长期持久缓存 |
| 诊断 | request_id、错误分类、耗时 | token、JWT、密钥、昵称正文、图像、密码或原始响应 |

## 3. 网络与缓存

业务使用 HTTPS，未来 IM 使用 WSS。使用系统证书链、主机名和有效期校验，不实现“始终信任”的 URLSession challenge。TLS 版本由平台支持协商，服务端禁用 TLS 1.0／1.1；首期不做自定义证书 pinning，以免本地 CA 与换证另引入不完整恢复机制。

Debug 的 127.0.0.1 回环 HTTP 仅用于虚构测试账号，独立测试数据目录、环境 ID 和客户端缓存命名空间。真实账号、Apple 登录以及所有真机请求使用 HTTPS。发布配置不包含 HTTP 地址或全局 ATS 放宽。Protobuf 是序列化，不是加密；不在其外另造网络密文协议。

认证与个人数据请求采用禁止磁盘缓存的 URLSession 配置；响应 Cache-Control: no-store。头像仍可用 ETag，但由 UserRepository 管理账号级加密缓存，HTTP 缓存使用 private, no-cache，禁止共享 URLCache 自动写明文。304 只在当前 environment＋user_id＋asset_id 已有可解密缓存时接受；否则无条件重取。网络二进制、解码图像仅在请求和显示期间存于内存，退出／账号切换释放旧账号引用。

## 4. SQLCipher 与账号密钥

每个 environment_id＋user_id 有独立随机 256 位数据库密钥及独立媒体密钥环，两者由 CSPRNG 分别产生，不共用、不从账号密码派生。Keychain 标识只包含用途、环境、账号与 key_id；值为密钥。采用 AfterFirstUnlockThisDeviceOnly，不参与 iCloud Keychain 同步；登录 token 包和存储密钥项分离，因此退出不会误删保留历史所需密钥。

首次创建账号库：确认身份 → 检查是否已有库／密钥 → 先可靠保存新密钥 → 创建并加密库 → 校验元数据和迁移 → 开放 Repository。只有从未存在的空存储可生成初始密钥；已有文件缺密钥属于故障，禁止静默新建密钥、重建空库或覆盖原文件。

打开库时先取密钥，在每个连接首次读取前配置 SQLCipher；再核对环境／账号元数据。DatabasePool、WAL、外键与 FTS 继续沿用业务设计。FTS 正文、投影和索引同库加密，不能在导出／重建时落明文中间文件。SQLCipher 保护数据库与 WAL 数据页，不承诺隐藏文件大小、访问模式及所有操作系统元数据。[SQLCipher 设计](https://www.zetetic.net/sqlcipher/design/)

代码阶段先验证远程依赖组合、iOS 15、设备与模拟器架构、FTS、DatabasePool、迁移、备份和 rekey 能力；确保没有同时链接系统 SQLite 与 SQLCipher 导致符号或配置混用。具体依赖版本与获取方式在可编译实验后锁定；不得因配置失败退回明文库再承载真实账号。

## 5. 媒体与资料快照加密

首期认证头像与小型资料快照使用 CryptoKit AES-GCM、256 位密钥、每次加密新生成的 96 位 nonce、128 位认证 tag。持久信封记录 format_version、key_id、nonce、ciphertext、tag；version 与 key_id 也参与附加认证数据（AAD）。原文长度、hash 只在已加密数据库或认证过的信封内保存。[CryptoKit AES.GCM](https://developer.apple.com/documentation/cryptokit/aes/gcm)

AAD 采用明确的长度分隔 UTF-8 编码，包含 environment_id、user_id、resource_id、用途、format_version、key_id；不使用含糊字符串拼接。解密时从当前账号与期望资源重建 AAD，不能只信任文件自报身份。认证失败、截断、未知版本、密钥缺失均停止消费，不返回部分明文，也不将其当作空头像成功保存。

完整信封格式是本地格式，不进入网络 Protobuf。密文先写 staging，完成认证回读后原子移动，再提交数据库引用；事务失败仅留下无引用密文。media_resource.relative_path 指向密文，byte_count／sha256 仍表示逻辑原文，密文体积另外记录，参见字段字典。

认证头像有既定大小限制，可以一次有界解密。未来 IM 大文件不能套用一次性读入内存；在接入视频／文件前单独冻结流式认证格式、分块顺序及完整性验证，验收通过后再开放该文件类型。当前不实现自制流密码或声称任意大文件格式已经确定。

## 6. 临时明文与系统文件保护

数据库、持久密文及加密 staging 保留 completeUntilFirstUserAuthentication；重启首次解锁前暂停存储工作。需要 URL 的系统组件通过租约获取受保护临时文件，使用 complete 文件保护，置于账号隔离的 Caches/DecryptedSessions，排除备份。内存可直接显示的头像不生成明文文件。

租约绑定账号 generation、资源与使用者。预览结束、分享回调完成、退出或切账号时关闭句柄并删除；进入后台先关闭相关预览并结束明文租约。启动时在恢复展示前清理上次进程遗留。正在使用且不能立即删除的文件停止新访问，关闭后重试，失败留待下次启动，不伪报已清理。禁止把受保护临时文件等同于应用层加密容器。

原件导入的系统临时文件不由应用随意清除；应用拥有的副本尽快加密，清理自己创建的明文 staging。文件删除不保证闪存物理擦除；用户主动分享后的外部副本不在应用控制范围内。

## 7. 轮换、备份和恢复

| 场景 | 规则 |
| --- | --- |
| 数据库换钥 | 暂停账号读写和观察，关闭连接池，保存新 key_id 与轮换状态，使用独占连接 rekey；新连接完整性验证成功后才切换有效版本 |
| 轮换中断 | 保留旧／新候选密钥与受保护状态记录；仅尝试该账号已登记候选，在完整性和身份核验成功后恢复，不盲删原库 |
| 媒体换钥 | 新写使用新 key_id，旧文件按各自版本读取；逐文件重加密、验证、原子换路径并提交引用，支持断点恢复 |
| 删除旧密钥 | 确认当前文件、同设备迁移备份、活动租约与未完成任务均无旧版本依赖后删除；不得只按时间删除 |
| 同设备升级备份 | 一致性加密数据库备份与受保护恢复清单；旧密钥留存到备份过期，不复制正在写的主文件代替一致性备份 |
| 系统跨设备恢复 | 首期所有账号库、媒体与临时数据排除系统备份；ThisDeviceOnly 密钥不迁移，不制造“有密文无钥”的自动恢复承诺 |
| 密钥丢失或损坏 | 封存原文件，显示不可恢复／重新登录及显式清理选项；未上传消息与本机草稿无法从服务端找回 |

轮换日志只保存状态、用途、key_id、资源 ID 和进度，不保存密钥或明文。库外轮换恢复清单只承载不含正文的最小信息，存储于受保护且不备份的位置。首次实际实现的 SQLCipher rekey 中断能力必须故障注入验证，不能仅依靠文档断言安全。

普通退出清除会话凭据和明文内存，保留加密历史及存储密钥。明确清理本地账号或服务器确认删除后，先停任务、结束租约并关闭库，再删除该账号文件／同设备备份，最后删除该账号存储密钥；失败记录清理任务，不影响其他账号。服务器删除无法保证离线旧设备瞬间擦除，本机再次得知账号停用后执行本机清理。

## 8. 实施门槛

先完成 SQLCipher 与密钥存取可行性验证，再实现账号数据持久化。登录阶段不必提前实现全部 IM 表，但资料快照必须使用上述 AES-GCM 保护，不留明文过渡快照。既有 local-demo 草稿迁移时先写入隔离的加密演示目录，核对成功并记录幂等结果后才清理旧明文副本，不能归给真实账号。

本轮没有运行加解密、重启、锁屏、Keychain、SQLCipher 或恢复测试，验收场景见 [验证矩阵](validation.md)。
